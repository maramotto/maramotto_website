# Plan: integrar Umami en maramotto.com

> **Para agentes:** los pasos usan checkbox (`- [ ]`) para ir marcando progreso. No inventes valores — los marcados como `<<PENDIENTE>>` los aporta Mara antes de empezar.

**Goal:** medir visitas y unos pocos clics clave en maramotto.com (home, páginas de proyecto y blog) con la instancia de Umami que ya corre en el servidor Hetzner, sin cookies, sin banner de consentimiento y sin meter un build step en las páginas estáticas.

**Arquitectura:** Umami ya está desplegado como servicio Docker en el mismo host que `maramotto-web` (ver `blog/README.md` → sección "Deploying", donde se listan los servicios `universopunzadas`, `umami`, `mujereshistoria`). No hay que instalar nada nuevo en el servidor. La integración es puramente cliente: una etiqueta `<script defer>` apuntando al host de Umami, replicada en las tres páginas estáticas y en el layout base del blog. Los eventos de clic se declaran con el atributo `data-umami-event`, que el propio script de Umami detecta solo — cero JavaScript propio.

**Contexto del repo que importa:**
- No hay templating en las páginas raíz: `index.html`, `cuerposonoro.html` y `universo-punzadas.html` repiten su `<nav>` y su `<head>` a mano. El snippet hay que ponerlo en las tres.
- El blog sí tiene layout compartido: `blog/_includes/layouts/base.njk` cubre listados, posts, páginas de tag y feeds.
- El `Dockerfile` es multi-stage: compila Eleventy y copia `_site/blog/` dentro de la imagen nginx. Un cambio en `base.njk` solo llega a producción tras `docker compose build`.
- Los tests E2E (Playwright) corren contra `http://localhost:8080`, que es el contenedor ya construido.

      Name: `maramotto.com` · Domain: `maramotto.com`.
      Al guardar, Umami genera un **Website ID** (un UUID tipo
      `a1b2c3d4-e5f6-7890-abcd-ef1234567890`). Cópialo.

- [ ] **Anotar la URL pública del panel** (el subdominio donde responde Umami).

- [ ] **Confirmar la ruta del script.** Umami v2 lo sirve en `/script.js`;
      v1 lo servía en `/umami.js`. Compruébalo abriendo
      `https://<host-umami>/script.js` en el navegador: si devuelve
      JavaScript, esa es. Si da 404, prueba `/umami.js`.

Valores a fijar antes de empezar:

```
UMAMI_SRC        = https://<<PENDIENTE>>/script.js
UMAMI_WEBSITE_ID = <<PENDIENTE>>
```

---

## Constraints

- **Sin cookies ni almacenamiento local.** Umami en configuración por defecto no usa cookies ni guarda datos personales. No añadir banner de consentimiento en este plan.
- **Nada de contar tráfico propio de desarrollo.** El snippet lleva `data-domains="maramotto.com"`, así que el script se carga pero no envía nada desde `localhost` ni desde la IP del servidor. Es la única salvaguarda: no añadir condicionales en JS.
- **Sin build step nuevo** para las páginas raíz. El snippet va escrito literal en el HTML.
- **Un solo `data-website-id` para todo el dominio**, blog incluido. El blog no es un sitio aparte en Umami.
- **Nombres de evento en kebab-case y en español neutro**, estables e independientes del idioma de la interfaz (el toggle ES/EN no cambia la URL, así que un evento por idioma no aportaría nada).
- No tocar `nginx.conf` en este plan.

### Task 3: Eventos de clic en proyectos y contacto

Umami dispara un evento personalizado en cualquier elemento con el
atributo `data-umami-event`. No hace falta JavaScript propio ni listeners.
`data-i18n` reescribe `textContent`, nunca atributos, así que ambos
conviven sin problema en el mismo elemento.

**Archivos:**
- Modificar: `index.html`
- Modificar: `cuerposonoro.html`
- Modificar: `universo-punzadas.html`

- [ ] **Paso 1: `index.html`** — añadir el atributo a estos elementos
      (localízalos por su `href` y su clase, los números de línea pueden
      haber cambiado):

| Elemento | Atributo a añadir |
|---|---|
| `<a href="cuerposonoro.html" class="btn btn--primary btn--small">` (CTA del proyecto destacado) | `data-umami-event="proyecto-cuerposonoro"` |
| `<a href="universo-punzadas.html" class="card__link">` | `data-umami-event="proyecto-universo-punzadas"` |
| `<a href="mailto:hello@maramotto.com" class="btn btn--primary">` | `data-umami-event="contacto-email"` |
| `<a href="https://github.com/maramotto" class="social-link">` | `data-umami-event="social-github"` |
| `<a href="https://www.linkedin.com/in/mara-crespo/" class="social-link">` | `data-umami-event="social-linkedin"` |

No instrumentes los enlaces del `<nav>` ni del dropdown: generan ruido y
la navegación entre páginas ya se ve en pageviews.

- [ ] **Paso 2: `cuerposonoro.html` y `universo-punzadas.html`** — buscar
      en cada una los enlaces de contacto (`mailto:`) y los enlaces
      externos al repo o a la demo del proyecto, y aplicar el mismo
      criterio de nombres:
      - `mailto:` → `data-umami-event="contacto-email"`
      - enlace a GitHub del proyecto → `data-umami-event="codigo-<slug-proyecto>"`
      - enlace a la web/demo del proyecto → `data-umami-event="demo-<slug-proyecto>"`

      Lista los elementos que encuentres antes de editarlos, para que Mara
      pueda revisar el criterio.

- [ ] **Paso 3: Verificar** que no hay nombres de evento duplicados con
      significados distintos:

```bash
grep -rho 'data-umami-event="[^"]*"' *.html | sort | uniq -c
```

### Task 4: Test E2E que protege el snippet

Los tres archivos raíz se editan a mano y es fácil que una página nueva
salga sin analytics. Un test barato lo evita.

**Archivos:**
- Crear: `tests/e2e/analytics.spec.js`

- [ ] **Paso 1: Escribir el test.** Recorre todas las páginas y comprueba
      que el script está exactamente una vez, con el ID correcto y con
      `data-domains` puesto:

```js
const { test, expect } = require("@playwright/test");

const PAGES = [
  "/",
  "/cuerposonoro.html",
  "/universo-punzadas.html",
  "/blog/",
  "/blog/en/",
  "/blog/hola-mundo/",
];

const WEBSITE_ID = "UMAMI_WEBSITE_ID";

for (const path of PAGES) {
  test(`${path} carga el script de Umami`, async ({ page }) => {
    await page.goto(path);
    const script = page.locator("script[data-website-id]");
    await expect(script).toHaveCount(1);
    await expect(script).toHaveAttribute("data-website-id", WEBSITE_ID);
    await expect(script).toHaveAttribute("data-domains", "maramotto.com");
  });
}

test("los CTA de la home tienen evento", async ({ page }) => {
  await page.goto("/");
  for (const name of [
    "proyecto-cuerposonoro",
    "proyecto-universo-punzadas",
    "contacto-email",
  ]) {
    await expect(page.locator(`[data-umami-event="${name}"]`)).toHaveCount(1);
  }
});
```

- [ ] **Paso 2: Levantar el contenedor y correr el test**

```bash
docker compose up -d --build
npx playwright test tests/e2e/analytics.spec.js
```
Esperado: todos en verde. Si el test de `data-domains` falla en alguna
página, es que falta el snippet ahí.

- [ ] **Paso 3:** confirmar que la suite existente del blog sigue pasando
      (`npx playwright test`). El snippet no debería mover ningún píxel,
      así que las capturas de referencia no deberían cambiar. **Si alguna
      captura falla, para y avisa** — significa que el script está
      afectando al layout y hay que investigar antes de seguir.

## Fuera de alcance (decidido, no olvidado)

- **Proxy del script bajo `maramotto.com`** para esquivar bloqueadores.
  Descartado por ahora: añade configuración de nginx y una superficie más
  que puede romperse. Si ves que las cifras parecen bajas frente a lo
  esperado, es la siguiente palanca.
- **Evento del toggle ES/EN.** El toggle no cambia la URL (guarda el idioma
  en `localStorage`), así que Umami no distingue idioma en la home. Se puede
  añadir después con un `umami.track()` en el handler de `js/i18n.js`.
- **Aviso de privacidad.** Umami sin cookies y sin datos personales
  normalmente no obliga a banner de consentimiento, pero yo no soy abogada:
  si quieres cubrirte, lo suyo es una línea en una página de privacidad
  diciendo qué se mide y con qué herramienta. No entra en este plan.
