# Blog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Markdown-driven blog at `/blog/` to maramotto.com, built with Eleventy, with ES posts translated to EN as an AI-assisted authoring step, per-post cover images (square or 16:9), tag filtering, RSS, and sitemap — without introducing a build step for the rest of the (currently 100% static) site.

**Architecture:** Eleventy (11ty) compiles `blog/posts/*.md` (paired `.es.md`/`.en.md` files sharing a `translationKey`) into static HTML under `blog/_site/blog/`. A multi-stage `Dockerfile` runs the Eleventy build in a Node stage, then copies its output into the existing `nginx:alpine` stage alongside the untouched static files (`index.html`, `cuerposonoro.html`, `css/`, `js/`, `img/`). Blog pages reuse the site's existing `css/style.css`, fonts, and `js/nav.js` via absolute paths; a new `css/blog.css` covers blog-specific styling. The language toggle on blog pages navigates between paired ES/EN URLs (resolved via `translationKey`) instead of rewriting text in place like `js/i18n.js` does elsewhere on the site.

**Tech Stack:** Eleventy 2.x (Nunjucks templates), `@11ty/eleventy-plugin-rss`, Node's built-in `node:test` runner for filter unit tests, Playwright for E2E/visual regression, Docker multi-stage build, nginx (unchanged).

**Spec:** `docs/superpowers/specs/2026-08-22-blog-design.md`

## Global Constraints

- No build step for the existing site pages (`index.html`, `cuerposonoro.html`); only `blog/` is compiled.
- No translation API calls or secrets in the build — ES→EN translation is a manual, AI-assisted authoring step producing a second Markdown file.
- Blog URLs: listing `/blog/` (ES) and `/blog/en/` (EN); post `/blog/<translationKey>/` (ES) and `/blog/en/<translationKey>/` (EN); tags `/blog/tags/<tag>/` and `/blog/en/tags/<tag>/`; feeds `/blog/feed.xml` and `/blog/en/feed.xml`.
- Every post front matter includes: `title`, `date`, `lang`, `translationKey`, `tags`, `image`, `imageRatio` (`square` or `wide`), `excerpt`.
- Reuse `css/style.css` design tokens (colors: `--purple`, `--purple-dark`, `--purple-light`, `--teal`, `--yellow-light`, `--dark`, `--text`, `--text-light`, `--white`, `--cream`; fonts: Syne + DM Sans) — do not introduce a new palette.
- Images: explicit `width`/`height`, `object-fit: cover`, `loading="lazy"` except the current post's own cover (`eager` + `fetchpriority="high"`).
- `nginx.conf` is not modified — clean URLs already work via `try_files $uri $uri.html $uri/ =404`.

```js
const WORDS_PER_MINUTE = 200;

function readingTime(content) {
  const text = String(content).replace(/<[^>]+>/g, " ");
  const words = text.trim().split(/\s+/).filter(Boolean);
  return Math.max(1, Math.round(words.length / WORDS_PER_MINUTE));
}

module.exports = readingTime;
```

```js
function translationUrl(posts, translationKey, targetLang) {
  const match = posts.find(
    (post) => post.data.translationKey === translationKey && post.data.lang === targetLang
  );
  return match ? match.url : null;
}
```

```js
const MONTHS_ES = [
  "enero", "febrero", "marzo", "abril", "mayo", "junio",
  "julio", "agosto", "septiembre", "octubre", "noviembre", "diciembre",
];
const MONTHS_EN = [
  "January", "February", "March", "April", "May", "June",
  "July", "August", "September", "October", "November", "December",
];

function readableDate(date, lang) {
  const d = new Date(date);
  const day = d.getUTCDate();
  const year = d.getUTCFullYear();
  if (lang === "en") {
    return `${MONTHS_EN[d.getUTCMonth()]} ${day}, ${year}`;
  }
  return `${day} de ${MONTHS_ES[d.getUTCMonth()]} de ${year}`;
}

module.exports = readableDate;
```

```js
const { test, expect } = require("@playwright/test");
```
